# Вход на сайт UNICON DTS

Логин: `unicondts2026`. Пароль хранится только в серверном окружении. При открытии сайта посетитель видит стандартное окно входа браузера. Общая пара подходит для всех приглашённых посетителей.

## Локальный запуск

1. Выполните `node scripts/create-access.mjs` один раз. Он создаёт случайный пароль и приватные файлы `.env.auth.local` и `access-private/credentials.txt`. Скрипт не выводит пароль в терминал и не меняет существующий пароль.
2. Откройте `access-private/credentials.txt` на своём компьютере, чтобы узнать пароль.
3. Запустите `npm run dev`. Если сервер уже работал до настройки, перезапустите его.

Оба приватных файла исключены из Git и из подготовленного архива исходников. Не публикуйте их. Для смены локального пароля отредактируйте `.env.auth.local` приватно и перезапустите сервер.

## Netlify: включение защиты опубликованного сайта

Эта защита использует Netlify Edge Function для **всех путей**, включая HTML, JavaScript, изображения и данные. Если пароль отсутствует в окружении, функция возвращает 503 и не пропускает посетителя к файлам.

1. Войдите в существующий проект `unicondts` в Netlify.
2. В Project configuration → Environment variables добавьте:
   - `DTS_AUTH_LOGIN` = `unicondts2026`
   - `DTS_AUTH_PASSWORD` = пароль из приватного файла либо выбранный владельцем пароль.
   Область доступа переменных должна включать **Functions**. Не используйте префикс `VITE_`. Пароль не следует добавлять в `netlify.toml`, GitHub, чат или статический архив.
3. Опубликуйте проект из исходников через привязанный Git-репозиторий или Netlify CLI. Для сборки используются `npm run build` и каталог `dist` из `netlify.toml`.
   Пример для уже авторизованного и привязанного CLI: `netlify deploy --build --prod`.
4. Убедитесь, что Netlify показывает развернутую функцию `site-access`. Проверьте сайт в приватном окне: без входа он должен возвращать 401 для `/`, `/assets/...` и `/world-countries.geojson`; правильная пара открывает страницу, неверная — нет.

**Загрузка одного `dist.zip` через перетаскивание не разворачивает Edge Function. Не используйте прежний статический архив для включения защиты.** До публикации Edge Function существующая публичная версия остаётся без изменений и без этой защиты.

При изменении пароля в Netlify требуется новый deploy. Общий пароль не даёт индивидуальных аккаунтов: если доступ нужно отозвать у одного человека, смените его для всех. Браузер запоминает Basic Auth на время своей сессии; для отдельной проверки используйте приватное окно. Уже скачанные до включения защиты копии сайта остаются у посетителей.

Документация: https://docs.netlify.com/build/edge-functions/get-started/ и https://docs.netlify.com/build/edge-functions/environment-variables/.
